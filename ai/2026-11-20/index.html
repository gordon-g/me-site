1. 医疗健康 AI 评测框架今日连发两版，把「没评上的」从「评了 0 分」里彻底拆出来：mirobody-eval v0.2.0 与 v0.1.0 同日发布

地址：https://github.com/thetahealth/mirobody-eval ｜ ★389 ｜ MIT ｜ 医疗与健康 AI Agent 的评测框架：虚拟用户、被测系统、裁判三者都是可插拔插件，五套基准共用一条 basic_runner 命令复现

事件内容

  • 今日发布 v0.1.0 与 v0.2.0 两个版本（两个 tag 发布时间戳相隔 2 秒），仓库 24 小时内 6 次提交，最后一次提交时间 2026-11-19T13:21 UTC。
  • v0.2.0 的核心改动写在提交信息里：feat(cli): one line per case by default, and no pass rate where nothing was graded pass/fail —— 默认每用例一行输出，且在没有任何用例被判为 pass/fail 时不输出通过率。
  • README 把这条规则列为设计要点，标题就叫「Ungraded is not zero」：超时、连接失败、裁判服务挂掉一律记为 error 并排除在平均分之外，同时每个汇总都必须把「未评数」和「已评分母」并排打印出来。
  • Web 端同步补上 feat(web): show where continuous scores fall in the report and tag bars，让连续分数在报告里显示它落在哪一档。
  • 另一处细节值得记：feat(web): lay the report list out as a table, and stop pricing unknown models as gpt-4.1 —— 未知模型不再按 gpt-4.1 的价格计价。

值得关注的原因

  • 这条规则和我上期从 nutrition-rag、schemagate 学到的「没跑就不报数字」是同一个方向，但今天给出了更硬的形式：不是不报，是把「没评」从「评了但不及格」里物理拆开。超时和不及格混在一个平均分里，等于让基础设施故障伪装成模型能力差。
  • 我的 4P 专家包那套 30~50 题两两对比评测，至今只有一个总分。今天该加的第一条字段是「未评数」——哪几题没跑起来、为什么没跑起来（超时 / 解析失败 / 裁判不可用），必须和分数并排显示，不能进分母。
  • 「未知模型不按已知模型计价」这条更值得抄。我的 GLP-1 营养伴侣第 61 版里，如果用本地模型跑某个模块，成本表里写的是云端模型的价格——那是在拿别人的单价编自己的账。
  • basic_runner 一条命令跑全部五套基准、报告带 batch id 和 sha256 校验和，这个「结果自带指纹」的形态，我的干预报告导出功能还没做：同一份报告在什么数据、什么代码版本下产生，应该可复现、可核对。

3. 可穿戴健康数据层今日一次性提交 27 笔测试改造，最狠的一笔是「别拿 mock 给自己作证」

地址：https://github.com/the-momentum/open-wearables ｜ ★2,808 ｜ MIT ｜ 自托管的可穿戴设备数据层：把 Garmin、Oura、Whoop、Polar、Apple Health、Samsung Health、Google Health Connect 等统一成一套 schema，用一个 REST API 提供，内置 MCP server 供 LLM 查询

事件内容

  • 24 小时内 32 次提交，最后一次为 2026-11-20T12:10 UTC —— 其中 27 笔集中在测试体系改造，剩下的 5 笔才是后端功能与安全修复。
  • 测试改造的方向非常一致：test: replace MagicMock httpx patches with respx routes（用真实路由替身替掉 mock 补丁）、test: replace sleeps and freezegun with time-machine（冻结时间替掉打桩时钟）、test: hash passwords with 4 bcrypt rounds instead of faking them（用真实 4 轮 bcrypt 替掉伪造的密码哈希）、test: assert API and SDK payloads with dirty-equals、test: generate provider payloads with Polyfactory、test: run tests in parallel with pytest-xdist。
  • 另有 5 笔后端提交全是边界收紧：fix(backend): fetch Garmin FIT files only from Garmin（Garmin 的 FIT 文件只允许从 Garmin 官方源获取）、fix(backend): persist rotated application secret（轮换后的应用密钥必须落盘持久化）、fix(backend): limit failed developer logins（限制开发者登录失败次数）、docs: correct provider token storage notes（修正文档里关于 token 存储位置的说明）、feat(backend): let extensions run their own Celery queues and emit webhook events。
  • README 里那句架构原则今天变得格外有分量：「Provider apps and tokens belong to you」—— 你用自己账号注册 Garmin/Oura/Whoop 的开发者应用，OAuth token 存在你自己的数据库里。

值得关注的原因

  • 「Garmin 的 FIT 文件只从 Garmin 拿」是数据来源不可伪造原则的最小实现：设备原始文件如果可以从别的渠道进来，用户就能通过改文件把自己的心率、步数、活动量改成任何值 —— 而这些数字会直接进入健康模型和保险定价。我的 4P 平台如果接第三方设备数据，第一条就该是来源校验。
  • 「别拿 mock 给自己作证」这条比那五条安全修复更值钱。 mock 替身只能证明「代码按我写的假设运行」，证明不了「真实 provider 的响应能被我正确解析」——test: replace MagicMock httpx patches with respx routes 和 test: hash passwords with 4 bcrypt rounds instead of faking them 是在把测试从自证循环里拽出来。我的 Flask+SQLite 后台目前第三方 API key 是直接写配置文件、测试里全是 mock，这条说明该补的正是「用真实 provider 的真实响应跑一遍」。
  • 「轮换后的密钥必须落盘持久化」是个很具体的运维坑：密钥轮换了但没落盘，重启后系统用回旧密钥，等于轮换从未生效。我的 Flask+SQLite 后台的第三方 API key 是直接写配置文件 —— 这条说明轮换和持久化必须成对设计，否则轮换是个假动作。
  • README 那句「数据平台不能成为中间人」是这个领域最该抄的一句架构原则：我的 4P 平台接第三方健康数据时，第一条校验必须是来源，不是格式。

5. 健康数据引擎今日把中文症状编码做成了显式规则：一条症状说两遍只算一条，「头晕嗜睡」要拆成两个才编码

地址：https://github.com/thetahealth/mirobody ｜ ★1,644 ｜ Apache-2.0 ｜ 自托管健康数据引擎：把化验报告、可穿戴数据与临床记录汇成统一数据层，供临床与营养研究使用

事件内容

  • 24 小时内 7 次提交，最后一次为 2026-11-20T04:47 UTC；同日发布 1.6.2 版本（11-19 09:16 UTC）。
  • 最硬的一条是 journal: write 头晕嗜睡 as two coded complaints, and code 嗜睡, 视线发糊 and a temple pain —— 提交信息里写明：一个自托管用户的日记原句「下午太阳穴跳痛、头晕嗜睡」之前两个主诉都没被编码。原因是 头晕嗜睡 作为整词匹配时无法编码，而只有 头晕 单独能编码；DeepSeek 有时把它返回成一个症状条目、有时返回成两个。
  • 新规则写得很克制：collect.sentence.plan 现在只在症状名是纯 CJK 时尝试拆分，且只有当恰好一刀能切出两半、且两半各自都能在症状轴上编码时才拆；头晕不嗜睡（否定的）、三个主诉、能整词编码的名字、有两种切法的名字，都保持模型原样作为一条。
  • 同时 symptoms_zh.tsv 扩充了中文词表：嗜睡/犯困/困倦 → AS99、视线模糊/视线发糊/看东西模糊 → FS05、太阳穴痛/太阳穴疼/太阳穴跳痛 → NS01。
  • 另两条同属「拒绝也要说得清楚」：resolver: refuse a hyphen split only on an immunoassay role word（只有当后一半是免疫分析的角色词时才拒绝按连字符拆分）、resolver: a role tail refuses only when the answer is the other role（角色词尾缀只有在答案确实是另一个角色时才拒绝，也就是「拒绝」这件事本身有条件）。

值得关注的原因

  • 中文症状词表 + 纯 CJK 才尝试拆分 + 只切一刀且两半都能编码 —— 这套规则我可以直接搬。我的 4P 平台要做中文主诉结构化，会撞上完全一样的问题：「头晕嗜睡」是一个词还是两个、「头痛头晕」怎么切、「头晕不嗜睡」怎么判否定。mirobody 今天的答案是：先扩中文词表（让 嗜睡、视线发糊、太阳穴跳痛 这些词本身能被编码），再把拆分条件写成可查、可测、可回归的显式规则。
  • 「同一条主诉说了两遍只算一条」实则是长期随访数据清洗里最容易出错、也最影响趋势判断的一类。我的 4P 平台要追踪客户三个月内的指标与主诉变化，如果客户两次就诊说「乏力」，被当成两次事件，趋势线就会多出一个假拐点。
  • 「拒绝要有条件」这一层更微妙：免疫分析里的角色词（assay、antibody 之类）后缀，解析器不能一律按连字符拆开，也不能一律不拆 —— 拆错方向会把一个检测项变成两个，把一个指标变成两个名字。
  • 这三条提交的共同点是「把边界情况写成显式规则，而不是靠兜底」。 这正是我 4P 平台的化验报告 OCR → 结构化那条路上最缺的东西：目前我的解析靠模型自由发挥，没有「同义词合并规则」「角色词保留规则」这种可查、可测、可回归的规则表。并且规则要写在词表里，而不是写在提示词里。

三、今日趋势观察

  • 「未评上」和「评了 0 分」被彻底拆开，今天有两个互不相识的项目在同一天收敛到这条原则。 mirobody-eval 今日两版连发，把超时 / 连接失败 / 裁判挂掉单独记为 error 排除出平均分，并强制把「未评数」和「已评分母」并排打印；fud-ai 的 Distinguish unreadable diary data from empty export range 在做几乎同构的事 —— 读不出来 ≠ 导出区间为空。缺失必须有自己的名字，不能借 0 的名义混进结果。这条应该直接进我的报告规范：每个数字后面要能回答「这个数是没测、是测了不及格、还是根本不该出现在这里」。
  • 技能生态今天同时长出两条「发布前必须过一道机器检查」的规则：一条在代码，一条在医学。 mattpocock/skills 用安装器自己的 YAML 解析器逐个验 SKILL.md 的 frontmatter；aipoch/medical-research-skills 的医学技能全部过自建的 MedSkillAudit 领域审计框架。共同点不是「加个 lint」，而是「用使用者实际会走的那条路径来验」。 我 4P 专家包的循证约束至今还是提示词里的自然语言要求，这个位置就是空的。
  • 可穿戴健康数据层今天做的是「数据来源与测试真实性」这一层的基础设施，而不是新功能。 open-wearables 32 笔提交里 27 笔是测试改造：用 respx 替掉 MagicMock、用 time-machine 替掉 freezegun、用真实 4 轮 bcrypt 替掉伪造哈希；另 5 笔是 Garmin FIT 只从 Garmin 拿、轮换后的密钥必须落盘、限制登录失败次数、修正 token 存储说明。这批改动的共同前提是「可信度来自它能被追溯到来源、且不被自己 mock 出来的结果骗过」 —— 数字能改、来源能冒名、测试能自证，那所有下游模型都在算噪声。我的 4P 平台接第三方健康数据时，第一条校验必须是来源，第二条校验必须是真实响应跑一遍。
  • 中文健康数据的编码规则正在被显式化，这是今天最贴近我业务的一条。 mirobody 今日把 嗜睡、视线发糊、太阳穴跳痛 写进中文症状词表，并把「纯 CJK 才尝试拆分、只切一刀且两半各自都能编码才拆」写成可回归的规则。它还诚实地写明了为什么以前没编码：头晕嗜睡 整词匹配时无法编码，只有 头晕 单独能编码。这正是我 4P 平台做中文主诉与化验项结构化时会撞上的同一堵墙，而且答案不是「让模型更聪明」，是「把词表和拆分条件写成规则」。
  • 医学 / 生信侧今天仍是「基础设施扎实、旗舰项目缺席」的一天。 ② 线 31 个仓库里，★1000 以上的只有 5 个，剩下大量是 Galaxy、anndata、salmon、histolab、ProDy 这些老牌科学基础设施在持续维护；aipoch/medical-research-skills 那种自曝「我 README 里的数字自己对不上」的项目反而是这批里最值得看的 —— 因为敢把不一致摊开讲，本身就是审计意识的一部分。 与健康 / 营养线（③，25 条）对比，③ 线的高星项目更少，但今天出现了几条可复用的具体做法：多密钥供应商轮询重试、隐私加固时剥离账号 ID 与粗化坐标、用真实 bcrypt 代替伪造哈希。
