五、精选 5 条（事件内容 + 为什么值得关注）

1. MadsLorentzen/ai-job-search — Agent 的第一个"白领流程"爆款

事件：单日 +2232 star 登顶 GitHub 日榜，总量 53.1k。项目本身不是产品，而是一套可 fork 的 Claude Code 工作流：读取岗位 JD → 对照个人经历打分 → 定制简历 → 生成 cover letter → 面试题库准备。整个"求职"被拆成可复现的 agent 步骤，用户 fork 后拥有自己的版本。
为什么值得关注：过去一年 agent 的杀手场景几乎都在软件工程内循环，这是第一次有非工程场景以"框架 + 技能"的形态冲到榜首，且增长快过同期所有 coding agent 本体。它验证了一件事：Agent 的扩散单位不是模型，而是"某个职业的完整流程模板"。对做垂直业务的人（包括医疗健康）来说，这是最可直接照抄的形态。
🔗 https://github.com/MadsLorentzen/ai-job-search

2. android/skills — 平台厂商开始自己定义"技能"

事件：Google 官方 Android 团队开源 android/skills（Kotlin，★8.8k，单日 +375），把 Android 平台开发能力整理成符合 Agent Skills 规范的技能包，供 Claude Code / Codex / Cursor 等调用。
为什么值得关注：此前技能库基本是社区自发（anthropics/claude-plugins-official、K-Dense-AI/scientific-agent-skills），质量参差。平台方亲自下场意味着两件事：一是技能格式可能像当年的 SDK 一样被平台锁定；二是"官方技能"会成为新的文档形态——以后查 Android API，可能不是读文档，而是让 Agent 调用官方技能。医学侧同理：谁先把自己的临床指南、HIS 接口做成官方技能包，谁就掌握了 Agent 时代的入口。
🔗 https://github.com/android/skills

3. Aperivue/medsci-skills — 医学技能库从"广"走向"深"

事件：★344，10-17 更新。这套技能只做一件事：把医学研究从选题到投稿的链路拆成可执行技能——文献检索、研究设计与报告规范、引用核查、统计分析、图表生成、投稿材料准备，兼容 Claude Code / Codex / Cursor / Copilot。
为什么值得关注：与上期推的 scientific-agent-skills（177 个技能横跨生信、化学、药物）形成鲜明对照。医学研究的真实瓶颈不是"知道得多"，而是"每一步都符合规范且可被审稿人核查"。这套技能把 CONSORT/PRISMA 这类报告规范变成了执行约束，而不是事后检查。做医学内容或临床研究支持的产品，可直接把它当质量基线来对标。
🔗 https://github.com/Aperivue/medsci-skills

4. xinxuxin/keystone-bench — 临床评测换了一个问法

事件：★808。基准不再问"这个临床问题答得对不对"，而是"当证据变了，你的行动会不会变"：给定同一患者场景，注入不同质量/方向的证据，观察助手推荐的检查、用药、转诊是否随之调整。
为什么值得关注：这是医疗 AI 评测的一个实质转向。此前 HealthBench 一类基准测的是知识正确性与安全性；keystone 测的是证据敏感性（evidence responsiveness）——临床上答案"永远不变"的模型其实更危险，因为它没有真的在读证据。这个维度一旦被广泛采用，会直接影响 RAG 类临床产品的设计：不是检索到就完事，而是要能因为检索结果而改变结论。
🔗 https://github.com/xinxuxin/keystone-bench

5. thetahealth/mirobody — 健康数据层"统一平台"路线得到验证

事件：★1.4k，10-18 更新。自托管 AI 健康数据引擎：把化验报告、可穿戴设备、基因数据统一摄入并转成可追溯的答案，内置 MCP 服务器；支持 Docker 部署 + 自带 LLM Key，或完全本地 llama.cpp 跑。
为什么值得关注：上期我们判断"健康数据层正从单点 MCP 收敛为统一平台"，mirobody 是目前最完整的样例——它不做某个设备（Apple Health / Garmin / Oura）的适配器，而是做摄入 → 归一 → 可追溯回答的全链路，并且把本地推理作为一等公民。对做健康管理或营养产品的团队，这是一个现成的参考架构：设备接入层可以外包给 MCP，真正的壁垒在归一化与"每个结论能回指到哪条原始数据"。
🔗 https://github.com/thetahealth/mirobody

六、今日趋势观察

  1. 技能层出现"官方供给"：android/skills 是平台厂商第一次用自己的仓库定义 Agent 技能。社区技能（几百到上千个）解决"有没有"，官方技能解决"敢不敢在生产用"。
  2. Agent 工程的焦点转向可靠性：今日基础设施榜上，task-state-guard（状态对账）、cayu（崩溃恢复/审批）、maka（append-only 审计）、astrid（能力沙箱）全部指向同一个问题——Agent 干到一半断了怎么办。这是从 demo 走向生产必须补的账。
  3. 医学 AI 评测进入"证据敏感性"阶段：从"答得对"（HealthBench）→ "说得清"（可审计）→ "证据变了你变不变"（keystone）。评测维度正在逼近临床决策的真实结构。
  4. 营养类项目集体"本地优先 + 判断型"：fud-ai、nutritrace、轻衡 全部零遥测自托管；功能上从热量记录扩到添加剂评分、过敏原检测、补剂循证。隐私不再是卖点，而是入场券。
  5. 值得警惕的噪音：今日 nutrition / healthcare-ai 主题下出现大量低质 SEO 仓库（同名 pubmed-mcp-server 一日内被复制多份、NourishAI-Forge 类模板站），选型时优先看提交历史与 issue 质量，别只看 star。
