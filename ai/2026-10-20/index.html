1. MedMCP：医学影像的 Agent 化，选择了"机房内"这条路

地址：https://github.com/medmcp/medmcp
发生了什么：10-19 更新，仓库定位是"开放医学影像工作流的 agent 生态"。医生/放射科/研究者用自然语言描述需求，由一个本地部署的模型负责规划，实际计算交给"经过测试的工具"。整套用 docker compose -f oci://ghcr.io/medmcp/compose:latest up -d 起，要求 Linux + NVIDIA GPU（建议 ≥24GB 显存）+ 容器工具链，服务在 localhost:8100。README 明确标注"仍在活跃开发，未获临床使用许可"。
为什么值得看：

  • 它把影像 AI 的交付单位从"一个模型权重"换成了"一条可执行工作流"——规划用 LLM、计算用确定性工具，这正好绕开"让大模型直接算像素"的可靠性陷阱。
  • on-prem 是硬约束而非选项：影像数据、患者元数据、结果都不出内网。这是医院采购时第一个会问的问题，MedMCP 把它写进了默认架构。
  • 对做医学影像产品的团队，这是一份现成的"合规形状"参考：本地模型 + 工具白名单 + 显存门槛 + 明确免责声明。

2. M4 v0.5.9：临床研究数据库的"临床语义层"开始按技能版本化发版

地址：https://github.com/hannesill/m4
发生了什么：10-19 12:00 发布 v0.5.9，变更集中在 vitrine-api 技能的图像示例与 Vitrine 0.1.5 的版本锁定；上一版 v0.5.8（10-18）刚加了 dataset catalog。M4 能把 MIMIC-IV、eICU 或自定义数据集快速初始化为本地库（可选 BigQuery），向上暴露 MCP 与 Python API，并附带"临床知识技能"。
为什么值得看：

  • 项目自己的判断很准：LLM 会写 SQL，但搞不定数据集特有的临床语义。"找脓毒症患者"在 MIMIC 与 eICU 里对应不同的表与筛查逻辑，M4 用技能把这类映射固化下来——这是知识工程，不是提示词工程。
  • 技能带版本号、带图像资源的发布方式（0.5.9 专门修技能里的图），说明临床技能已经进入"要维护、要回归"的工程阶段。
  • 对做真实世界研究（RWD）的团队，这是"可复现"的关键一环：同一句话在不同数据集上产出临床等价的查询。

3. ai-memory：编程 agent 的记忆正在变成跨厂商的基础设施

地址：https://github.com/akitaonrails/ai-memory
发生了什么：当日 +666★，10-20 07:18 仍在合并 PR（#1469/#1470，把 OpenCode 的 Haiku 5.5 路由到 Messages、补 MCP 工作区查询冲突测试）。项目是 Rust 写的长期记忆层，v3.1.1 于 10-17 发布，支持 20 多个 harness（Claude Code、Codex、Cursor、Gemini CLI、OpenCode、Grok、Devin、Kimi、Kiro 等）共用一份记忆。
为什么值得看：

  • 它解决的是"换工具就失忆"这个真痛点：在 Claude Code 里干到一半退出，切 Codex 进同一目录，接手的 agent 能拿到"停在哪、什么失败了、还有什么没定"的交接包。
  • 关键设计是 handoff 被定义成带 owner、只能被领取一次的强类型协议——把"多 agent 协作"从口头约定变成状态机，这对多 agent 流水线的正确性影响很大。
  • 隐私边界写得清楚：远程服务只收 harness 与会话标识，不收本地 transcript 路径与正文。这是记忆类工具最容易被质疑的地方，它先回答了。
  • 顺带一个信号：headroom、billion-context、ai-memory 同日冲榜，说明"上下文/记忆"已是编程 agent 竞争最拥挤的一层。

4. HealthClaw Guardrails：FHIR 与 MCP 之间缺的那层，有人在补了

地址：https://github.com/aks129/HealthClawGuardrails
发生了什么：10-20 05:00–07:14 连续提交，围绕 10-18 的"患者走查"修了六个信任断点（#998），并补了每日消息限额的重置说明（#864）、第 2/7 天回访邮件（#992）、上传文件的文件选择器（#860）。项目自我定位是"AI agent 与临床数据之间的开源安全层"，提供 29 个 MCP 工具、PHI 脱敏、不可篡改审计、step-up 认证、租户隔离，支持 FHIR 多版本，也能作为 Claude 插件安装。
为什么值得看：

  • README 里那句话点到了要害：FHIR 标准化了数据结构，MCP 标准化了连接方式，中间那层护栏没人标准化。这层恰恰是医疗 agent 能不能上生产的分水岭。
  • 它的开发方式值得学：不是先写架构文档，而是做"患者走查"（patient walk），用真实使用路径去找信任断点，再把每个断点变成 issue 编号。医疗软件的可信度就是这样一条条补出来的。
  • 诚实度也在线：明确声明所有记录是合成的、聊天用第三方模型"四选一"、尚无临床医生签字。医疗 AI 项目敢把这些写在首屏，比多讲十个功能点更有说服力。

5. FoodGuard v1.0.8：营养类应用开始"自曝数据集底牌"

地址：https://github.com/qjngbac/FoodGuard
发生了什么：10-19 16:27 发布 v1.0.8 并同步 APK。产品完全离线：扫码或拍配料表，端上解析、识别添加剂、比对 GB 2760 使用规定与营养国标，给 A/B/B-/C/D 五级评级并逐条开账（AP/NP/PP 扣分）。知识库规模：559 种添加剂、654 个别名、260 条限量规则、405 种原料、3012 条离线商品、10,970 条品名字典、44 条人群规则。81/81 测试全绿。
为什么值得看：

  • 这是一条和"拍照估卡路里"完全不同的技术路线：规则+国标而不是视觉大模型估值。对配料表这种"文本即事实"的场景，规则引擎的准确率与可解释性都更高，还能离线。
  • 最值得注意的是 README 主动披露：内置 3012 条商品里"大部分是脚本等差生成的示例编号，校验位合法但不等价于可扫中的真实商品码"，并提醒不要把它当实测覆盖率。在营养 App 普遍拿"百万食物库"当卖点的环境里，这种自我拆台反而是可信度信号。
  • 对做健康/营养产品的团队，这是一个可直接复用的合规范式：端上计算、国标兜底、扣分可追溯、数据集边界写清楚。

六、趋势观察

  1. 医疗 Agent 的竞争点从"能力"移到"中间层"。MedMCP 管工具与数据不出院，HealthClaw 管 PHI/审计/认证，M4 管临床语义，Hospilot 管可观测性——四家都在做"模型之外"的事，且都默认自托管。
  2. 临床技能开始有版本号。M4 的 0.5.9 专为技能里的图像资源发版，意味着技能不再是 README 片段，而是要回归测试的软件资产。这与前几期"技能库规模化""技能人格化"是同一条线，但进入了维护期。
  3. 上下文/记忆层成为编程 agent 最拥挤的赛道。当日 ai-memory、headroom、billion-context 三个不同路线（跨 harness 记忆 / 压缩 / 长会话）同时冲榜，说明模型能力趋同后，工程价值集中在"给模型喂什么"。
  4. 健康数据的入口在被硬件厂商收编。COROS 出官方 MCP、Zepp 出自托管桥接，加上此前的 Garmin/Polar 社区方案，"一个品牌一个 MCP"正在变成事实标准，第三方聚合平台的生存空间被压缩。
  5. 营养类出现"离线 + 国标 + 数据诚实"的第三条路。既不是拍照估值，也不是云端口径，而是端上规则引擎 + 明确的数据边界声明。对中国市场的健康类应用，这可能是最容易过审也最容易建立信任的形态。
  6. 官方技能/插件仓库成为厂商产品线。Cursor 的 plugins（13,057★）当日仍在合 PR，Anthropic 的 claude-plugins-official 也在榜——插件目录已经和 IDE、CLI 一样需要日更维护。
