5. 验收独立于执行：verifylens 首次进入 JetBrains，把「设置了状态」与「验证了状态」分开

地址：https://github.com/DamunKorea/verifylens ｜ ★0 ｜ MIT ｜ 逐条需求判定 AI 生成的改动是已被验证、与需求不同、还是尚未验证，本地运行不调用任何模型

事件内容

  • 今日 28 次提交，发 v0.21.0，并首次提供 JetBrains 预览版 0.15.0（内含同一套 0.21.0 引擎）；此前两日已发 jetbrains 0.14.0 与 0.14.1，修的是「通过映射盘或链接打开的项目」。
  • 0.21.0 的核心规则：a block that only sets a state is not the check for it——只把状态设成某个值的代码块，不构成对该状态的验证。这与它 2026-11-21 版本已在检测的「改了测试让它变绿」是同一问题的两个面。
  • JetBrains 侧同时补了 README 的状态表，并把 CLI 的 --lang 缺省行为改为跟随系统语言；CLI 包检查改为「从 tarball 安装这个 commit」，并支持 npx -y github:DamunKorea/verifylens 不安装直接跑。
  • 状态机被明确列为三态而非二态：verified / different / not yet verified。

值得关注的原因

  • 这是今天最该抄走的一条设计：验证必须由一个独立于实现的环节来判定，且判定结果要区分「已验证 / 有差异 / 尚未验证」——「尚未验证」不能被折叠进「有问题」或「没问题」。我上一期已经学到「三态」这个概念，但今天这个项目给的是更具体的判据：什么叫「验证」？改了状态 != 验证了状态。
  • 我的 4P 专家包 30~50 题两两对比评测，题目和打分都在我手上——这正是「改了测试让它变绿」最高发的场景。verifylens 的三态判定加上它「本地跑、不用模型」的特性，意味着这条防线可以在 CI 里常驻，不消耗任何 token。
  • 「执行与验收分离」这条线今天不止一家在做：Innei/ryugi 写明 only results of the work become claims, routine checks are one line；CopperTide/Shakedown 做成可回滚的世界副本、可以从任一步分叉比较不同运行；srpadmanabhuni/agentest 做 165 个离线确定性测试、不用 LLM 判分；MontrealAI/proof-gradient 让每次运行都留下证明；YusefSyed/tool-effect-bench 按沙箱数据库状态而非对话记录给提示注入打分。五个互不相识的项目在同一周收敛到「执行与验收必须分开」这一条上，这个密度值得记。
  • 它的许可证 MIT、星标 0、代码量不大——这类「小而硬」的验证工具，正是我这种一人公司最该先抄的：不是引入平台，是抄一条判定规则进我自己的规范。

三、今日趋势观察

  • ⭐⭐⭐ 证据强度被写进产物本身，成了今天最完整的一条主线。 今天至少有六个互不相识的项目在做同一件事——把「我的结论有多硬」显式写出来，而不是让读者自己猜。TomoOkuyama/clinosim 要求有医嘱存在才允许写「管理已开始」，门诊记录不得断言未记录的家庭自测；jgravelle/jcodemunch-mcp 规定没有 go.mod 覆盖的 Go 文件永远不算死代码，且 C/C++ 调用方只匹配到文本时会明说；Steinbeck-Lab/Orthonym 的命名要过 OPSIN 往返校验、引擎宁可拒绝也不猜；Kinprove/genealogy-research-recipes 的 provenance 报告把「已审核的来源记录」与「仍待审核的」分列；mims-harvard/ToolUniverse 修了 11 个「声称有断言、实际什么都没断言」的 schema；ryuxdsgn/design-intelligence 检查报告的门禁行与明细行是否统计了同样的区域。六团队、六生态、同一件事。 对我这一行最直接的映射是：我的干预报告里每个结论都应该能回答三个问题——依据是什么、证据有多强、哪些部分还没验证。 目前这三样一个都没有。
  • ⭐⭐⭐ 拒绝比猜测好，而且拒绝必须 fail-closed。 今天有一批项目把「不做」也写成了明确行为，而不是默默放行：the-omics-os/lobster 的 write_file 拒绝覆盖本次会话已加载过的文件、导出同样拒绝覆盖，且导入文件按身份而不是路径字符串识别；DylanCosto/pasta 在损坏的 codec 流上直接失败而不是 panic；Exelka/ExelCode 在连续失败且文件无变更时停掉智能体循环；clinosim 的叙述只写记录里有的东西。这对我上一期记下的那条「0 表示没有记录，存成 null」是同一件事的更完整版本——不只是「把缺失记成缺失」，而是「在证据不足时，产物必须拒绝生成，而不是生成一个看起来合理的东西」。我的 GLP-1 营养伴侣在指标读数不可信时，现在仍然会给出一个数。
  • ⭐⭐ 确定性基线正在成为默认配置，而不是可选项。 srpadmanabhuni/agentest 的 165 个测试离线、确定性、不用 LLM 判分；YusefSyed/tool-effect-bench 按沙箱数据库状态而非对话记录给工具型智能体的提示注入打分（188 样本 / 17 模型 / 5,628 次计分）；anandapurva55/multi-source-mcp-benchmark 把 MCP 服务器关在无网络 Docker 沙箱里做冲突证据评测；CopperTide/Shakedown 用可回滚的世界副本支持从任一步分叉比较运行；MontrealAI/proof-gradient 让每次运行都留下证明。这些和「谁来给自己打分」是同一个问题的两面——我的 4P 专家包两两对比评测目前是「LLM 出题 + LLM 出答案 + LLM 打分」的全闭环自评，这五个项目今天同时指向同一个结论：自评闭环必须有外部钉子（确定性测试、状态快照、独立断言），否则改一下题目就能改出好成绩。
  • ⭐⭐ 单位与口径的确定性，今天在健康线是主要动作。 timor-m/fnos-app-health-records 补了 FT3 与 T4 的双向单位换算并更新了肌红蛋白与嗜中性粒细胞的指标字典定义；noharm-ai/backend 让最大剂量合计不再把 schema 里的频次列表重复算进去；OpenStrap/edge 把 0-100 压力分的下限调低，让糟糕的夜晚不再被读成 0；youssofal/MTPLX 的 README 改成先写实测速度与「哪一套包适合哪一台 Mac」。这四条是同一类修正：把「同一个量在不同地方含义不同」这件事堵死。 我的补剂方案里单位换算与阈值判定是最容易出错也最不容易被发现的地方——双向换算 + 有测试，这两个条件缺一不可。
  • ⭐ 交付物开始显式标注「这一部分我给的是近似」。 alchaincyf/huashu-design 写明「自己的对比图写明是近似，真效果请用户在预览卡里点」与「交付包写明非系统字体用在哪些字上，提醒回退时别折行」；Innei/ryugi 写明「只有工作的结果才成为主张，例行检查只写一行」；brmel/farkad-ai 的报告打印 p50 与 p95 秒数以及输入的缓存占比；industrial-aiops/industrial-aiops 的文档专门区分「0.35 参考场景」与「候选试验」。「近似」和「参考」这两个词今天被反复写进交付物——这是我从别处学不到的补充：不仅「没跑就不报数字」，还要「跑了但只是参考，就标成参考」。
