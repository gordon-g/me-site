1. 模型之外还要有一层「认知层」：Empirica 用 13 个向量和一道 Sentinel 门，把智能体的过度自信变成可拦截的事

地址：https://github.com/EmpiricaAI/empirica ｜ ★257 ｜ MIT ｜ 在模型之外加一层的智能体可靠性测量框架：13 个认知向量、带证据分级的四层记忆、行动前的 Sentinel 门禁，以及用确定性检查校准置信度的三向量模型

事件内容

  • 今日 25 次提交并发 v1.17.18（2026-11-25 15:17）。README 给出的规模数字是 13 个认知向量、240+ 条 CLI 命令、26 个随插件提供的技能、以及 600+ 次真实工作会话的经验来源——注意 README 明确写了这 600+ 次会话并未公开数据集与抽样方法，因此不能等同于公开 benchmark。
  • 架构的核心是一条事务化的循环：每个任务被拆成 transaction，走 PREFLIGHT（我现在知道什么）→ CHECK（我准备好动手了吗）→ POSTFLIGHT（我学到了什么），其中 NOETIC 阶段负责调查、检索、阅读并记录 findings / unknowns / dead-ends，PRAXIC 阶段负责实施，Sentinel 卡在两者之间。
  • Sentinel 门禁用域相关且随关键性缩放的阈值，而不是一个固定阈值：README 原话是「cybersec/high is stricter than default/low」，而且模型自身校准结果较差时阈值会自动收紧。没通过 CHECK，智能体应该继续调查，而不是去改代码。
  • 置信度校准采用三向量模型：self-assessed（自评）、observed（从确定性检查里观测到）、AI-reasoned grounded state（带理由的 AI 推理状态）。它的判断标准是「此前表达的信心是否被测试、lint、静态检查这类确定性结果支持」，而不是把模型语气里的确定程度当成证据。
  • 记忆层把 findings、dead-ends、assumptions、mistakes、decisions、unknowns、falsifiers 分开建模，每条带 provenance 与 confidence，过期或错误的内容可以被 retract、被新认识 supersede，检索按任务相关性做语义匹配。四层记忆里还专门放 epistemic-gardening 技能：在记录过期 claim 或发布前，解析、撤回并清理 artifact graph。
  • 预测（forecast）不是普通计划项，而是带方向、置信度、支撑证据、以及什么情况能推翻它的可证伪记录，落地或失败后接受评分，并且按证据强度区分 measured / reviewed / reported / inferred——README 的规则是「weaker evidence cannot carry a higher confidence」。

值得关注的原因

  • 这一条正面回答了我这半年最核心的那个问题：我的「零 AI 幻觉」到底靠什么保证。 我一直把「强制循证 + 参考文献 + 零 AI 幻觉」写在每一份产物上，但它一直是一句自我要求，不是一套可执行的机制。Empirica 把它变成三个可以落地的字段：每条结论的证据等级、每个未知项的显式记录、每次行动前的门禁。 落到我自己的项目上，翻译过来是三件具体的事：干预报告里每个数值要带证据分级、方案里「没查到的部分」要显式写出来而不是留白、以及在推荐某个补剂之前，先检查我是否真的掌握了它的禁忌与相互作用信息——这就是 Sentinel 门禁在营养干预场景里的形态。
  • 「模型语气里的确定程度不等于证据」这一条，正好命中我公众号内容最常见的翻车点。 我转述研究时最容易丢的就是限定语——样本量小、单一族群、观察性研究，这些在原文里清清楚楚，转述后就没了。三向量校准模型给的是一个可操作的判据：我说「某某有效」的时候，这个「有效」是被研究设计支撑的，还是我读到了作者的乐观措辞？ 这条纪律比任何提示词模板都更接近根因。
  • 「weaker evidence cannot carry a higher confidence」这句规则，我准备直接抄进我的内容生产规范。 它把「证据强度」与「结论强度」绑在一起——证据弱的时候，结论就必须弱。我的公众号读者里有相当一部分是拿结论直接做决策的，如果我在转述时把证据等级和结论强度脱钩，就是在制造风险，而不只是不够严谨。
  • 诚实地说，它今天的自我限定也值得我警惕：README 明确写了没有公开的对照成功率、没有 Sentinel 拦截精确率、没有第三方复现。 这意味着它现在是一个设计思路值得抄的框架，而不是一个可以直接依赖的性能保证。我的态度应该是「抄它的结构，不引它的数字」——这恰恰也是我给自己的内容定的那条规矩：只引用能追溯到原文的一手结论。
  • 和它配套的第 4 条 grainulation/grainulator 是同一条主线的另一个切面，两条一起看才完整：Empirica 管的是「智能体自己知不知道自己知道什么」，grainulator 管的是「这次任务的证据账本有没有被留下、有没有被挑战过」。一个管内在校准，一个管外在留痕。

值得关注的原因

  • 「智能体跑在隔离的 home 里、插件与 hooks 全部禁用、密钥只走环境变量」这一组约束，就是我 WorkBuddy 工作区里 skill 与 expert 包该有的样子。 我每天在各种宿主里跑技能，如果某个技能能偷偷挂 hook 或读到别的凭据，我的整个工具链就没有边界了。「用隔离换信任」这个取舍，和我上期记的「扫描器不执行技能代码」是同一条线的两种做法。
  • 「DamoATrace 单独负责证据记录」这个架构值得我直接借鉴到自己的内容生产流程里。 我现在的做法是：AI 生成 → 我人工核对 → 改 → 发出去。中间那一步的核对痕迹没有留下来，所以下次同类问题我还要重新核一遍。如果有一个独立的「证据记录层」，把每次引用的原文、判定依据、修改理由都留下来，我的内容生产就变成可累积的，而不是每次从零开始。

  • 「本地优先 + 自带模型 + 技能化方法」这三个特征，正好是我想做的「考证钩子 + 营养 AI 内核轻量助手」应该长成的样子。 我的 GLP-1 营养伴侣已有 153 个食材模板与 15 个功能靶点，但这些知识现在是写死在代码里的，不是可被复用的技能。 ScholarSeed 让我看到另一条路：把「怎么用证据做一个营养判断」写成技能，而不是写成 if-else。
  • 今天只有 50 星、47 次提交，是个刚起步的项目，我不会因为它的架构漂亮就当它是成熟方案。 但「缓存隔离」「沙箱化智能体」「证据单独成层」这三件事，是我做 4P 平台时迟早要碰到的工程问题——今天先看到别人的解法，比我半年后自己踩一遍要划算。

  • 它同时支持 Ollama 完全离线，这一点对我这种「每周只有 8 小时、现金跑道约 1 个月」的一人公司是硬约束级别的。 我确实在本地跑 qwen2.5:7b，但那个模型做不了「2.4 亿文献源 + 引文网络」这种检索。它把「本地可用」和「证据级检索」这两件我原本以为二选一的事摆在了同一个产品里。

值得关注的原因

  • 「Auto 清单 / Manual 清单」这个二分，是我这期看到的最实用的一行设计，而且它恰好对应我「每周 8 小时」的真实处境。 我现在的所有 AI 工作都混在一起——没有区分「哪些能自动继续」和「哪些必须我亲自拍板」，结果就是我每周花不少时间在做本该自动的事，而真正需要判断的事又挤在最后没时间做。把「智能体可以自己继续」和「需要你介入」显式分成两张清单，这个分类本身就有价值，哪怕我不装这个工具。
  • 它把「证据等级」和「溯源」做成了记录字段而不是叙述语气，这和我上期记的 LesionAgent 那个判据是同一条线。 我上期写下的判断是「决定差距的是框架不是模型」；这一期两个仓库给了这个判断两个具体形态：Empirica 是内在的（智能体是否真的知道它知道什么），grainulator 是外在的（这次任务的证据有没有被留下并被挑战过）。 我的内容生产缺的正是后者。
  • 「导出无需凭据」这条细节，对一个要把证据带出工具的人来说是刚需。 我的产出要进公众号文章、要进 Word 报告、要进客户方案，证据账本必须能脱离原工具存在。这一条看似是实现细节，实际决定了这个方法能不能进我的真实流程。
  • 它主动写清楚「per-pass limits 不是一个会话级花费上限」，这种自我限定在我看过的同类项目里很少见。 这条恰好提醒我一个更实际的问题：我给 AI 的预算约束必须是会话级的，不能只靠单次调用上限。 我给 WorkBuddy 设的模型预算、以及我给自己的 API 账费，都还没有会话级的硬约束——这是我一人公司最该先补上的护栏，因为超支是唯一一种会立刻致命的失败。
  • 今天的 10 次提交都落在「MCP 质量与回滚安全」上，而不是新功能。 这本身是个信号：这类工具的难点不在造功能，而在保证「装了插件之后不会把已有环境搞坏」——README 里那句「Protect native MCP setup and document profile-safe upgrades」说的正是这件事。我的 WorkBuddy 插件与专家包生态，最终也会撞上同一道题。

三、今日趋势观察

  • ⭐⭐⭐ 「智能体可不可靠」这个问题，今天被拆成了两个可以分别落地的工程层。 EmpiricaAI/empirica 治内在：13 个认知向量、带证据等级与可撤回的记忆、Sentinel 在「我认为我懂了」与「我动手改」之间设一道按关键性缩放的闸、置信度用 self-assessed / observed / grounded 三个向量对齐确定性检查的结论；grainulation/grainulator 治外在：带证据等级的声明账本、冲突检测、弱支撑提示、Auto / Manual 两张清单、导出无需凭据。两个仓库的作者都在 README 里主动写了自己没有证明什么——Empirica 承认没有公开的对照成功率与 Sentinel 拦截精确率，grainulator 承认「编译器检查的是账本里记录的结构与支撑，不是来源是否为真」。这种坦白本身就是行业在成熟的一个标志：昨天我还在记「把证据强度写进产物」是少数派做法，今天有两个互不相识的团队同时在做，而且都把自己的边界写在了首页。
  • ⭐⭐⭐ 「引用可追溯」正在从一句承诺变成流水线上的几个具体工位。 wdcpclover/ai4paper 把「逐条比对权威数据库、识别 AI 编造的假论文」做成一个功能，把期刊分区与影响因子做成文献列表的默认列，把 3000–5000 字综述里每个观点都挂上真实文献编号；alibaba-damo-academy/ScholarSeed 把引用溯源与证据单独成层（DamoATrace）放在一起，并明确写着「引用只让你能回去查，不等于结论成立」；mims-harvard/ToolUniverse 今天修的仍然是「声称有断言、实际什么都没断言」的 schema。三处指向同一件事：AI 写的东西要能被逐条追回原文，而不只是附一个看起来像链接的东西。 对我这一行最直接的映射是：我的每一篇公众号文章，引用应该能在发出之前被批量核验一遍存在性与支持度，而不是发出去之后再祈祷没引错。
  • ⭐⭐⭐ 健康与营养这一线今天出现了一整批「本地优先、账本可追溯」的 MCP server，形态之统一超出预期。 Jihaochang1/foodcalorie-mcp 是中国食品与连锁餐饮营养数据（103 项免费条目 + 14 个品牌 116 项菜单，热量数据 116/116 附来源链接）；getwimsta/wimsta-mcp 把 BMI、体脂率、基础代谢率、每日总消耗与最大心率全部按公开公式给出「诚实的区间」而不是一个假装精确的数字；MetExplore/mcp-metexplore 把 INRAE 的代谢网络分析接进智能体并进了官方 MCP registry；Jasonatafricanow/Nutrition-Tracker-MCP 是「更正可追溯」的家庭营养账本配本地 SQLite 看板；pandefen1983/ingredient-audit-skill 是可审计的配料表筛查智能体，配多平台来源与证据分级。五个互不相识的团队，同一天，各自做了同一件事：把一个原本躺在 PDF 与 Excel 里的营养事实，变成智能体可以调、且调用记录可查的结构化接口。 这几乎就是我的 GLP-1 营养伴侣想接的东西——而它们的共同选择是「本地 SQLite / 自托管 MCP」而不是大厂 API。
  • ⭐⭐ 「相关还是因果」和「表现不好的时候怎么办」，正在被写进产品而不是藏进免责条款。 averagejoematt/life-platform 在 README 第一屏就写「一切只是相关、绝不作因果，全部标注置信度，而且表现不好的几周照样展示出来」，并且把「智能体被所有者裁定关闭、记录已对齐」当成一条正式提交；epic-open-source/seismometer（Epic 开源的医疗 AI 评估套件）强调的也不是跑分，而是在本地患者人群上验证模型、评估队列公平性、分析干预对结局的影响；arshleenn-kaurr/clinical-evidence-reasoning 干脆做可复现基准来测「临床证据互相冲突与依次给出时模型怎么推理」。三个仓库从三个角度指向同一件事：在健康这个领域，「诚实标注不确定」正在从道德姿态变成工程要求。 这对我的直接影响是——我的干预报告里「相关」两个字必须真的出现，而不是被「改善」「提升」这类词悄悄替换掉。
  • ⭐⭐ 智能体开始被当成分散的、可观测的、可远程驾驭的执行力，而不是一个对话框。 WenyuChiou/agent-board 是本地看板，显示每个智能体在做什么、哪一个在等你；gaixianggeng/mimi-remote 让你用 iPhone 看进度、批授权、改需求；Eslamasabry/opencode-mobile-next 在安卓上跑 Claude Code 与 OpenCode 并能远程插手；intentic/intentic 的自我描述很直接——「少一点 AI 味，多干一点活」；ESCOffier-labs/brigadestack 的定位是「在任何地方跑编码智能体并保留一份工作记录：共享任务、认领机制与进度追踪」。这条线对我这个只有一台 Mac、每周 8 小时的一人公司特别现实：我不缺想法，缺的是「让已经在跑的活儿在我不在电脑前的时候继续跑、并且我能看见它卡在哪」。
