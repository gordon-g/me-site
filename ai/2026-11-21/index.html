  • 「0 表示没有记录，存成 null」这条是我 GLP-1 营养伴侣第 61 版最该立刻修的一个 bug。 客户端上报体重为 0、步数为 0、热量为 0 时，我现在的处理是「跳过这一条」—— 那和「用户今天没吃」在数据上无法区分。这个区分一旦丢了，后面所有趋势计算都会把缺失误读成恶化。

三、今日趋势观察

  • 今天最值得记的一件事，是六个互不相识的项目同时给「未经证实」单独设了一个状态。 conveyor-belt 把「未评分的一次尝试」从分数与 95% 区间里拆出来；clinical-research-orchestra 让没有 PMID/DOI 的来源只能标 MANUAL、永不计入已验证；uibc-core 的裁决是三值的，证据不足时输出 INCONCLUSIVE 而不是 FAIL；body-model 把「没测到」存成 null 而不是 0；verifylens 专门识别「改了测试让它变绿」这种伪通过；kaijian-kaichi 在健康评估里把判定口径明确分成「数据不足 / 数据待补」，并规定数据不够时不生成结论、只提示还缺什么。六个团队、五个生态、同一件事 ——「没验证过」必须是一种能被表达、能被存储、能被查询的状态，而不是「没问题」的同义词。 这条我上期从 mirobody-eval 学过一次、这期又学一次，两次形态完全不同却指向同一个缺口，说明它是我这类项目最容易漏掉的结构性缺陷。
  • 「结论要能被外人离线复算」今天从理念变成了可下载的工件。 uibc-core 发布的语料带 SHA-256 与 231,243 字节的大小声明，还提前公布「对所有输入一律接受的验证器只能拿到 6/36」；yuxuan-huang-data 今日发 v2.1.0，用盲法人工参考测出两张医院交叉表的精确率并把标签公开（发布说明写明「Until now their quality was assessed indirectly; it is now measured against a blind human reference, and the labels are published」）；body-model 把来源指纹、世代号与新鲜度栅栏做成模型发布的一部分。三者的共同点是把「请相信我」换成了「请自己算」。 我的干预报告导出功能至今没有复核包 —— 一份报告应该能被第三方核对，而不只是被阅读。
  • 执行与验收分离，今天在三个生态同时成为硬规则。 conveyor-belt 用第二个模型评审 + 独立的修复会话；wicked-crew 明确写着「Runs your coding agents in sandboxes; a different agent reviews the work against your rules, and app changes pass acceptance testing before delivery」；Arc-Science 把这一条写进了产品定义 —— 「The agent that does a task never accepts its own work, and each step goes into a hash-chained ledger.」 再加上 verifylens 今日 v0.19.0 发布的正是「检测被改写的测试」，这四件事拼起来是一套完整的「谁可以给自己打分」的答案。我的 4P 专家包 30~50 题两两对比评测，题目与打分都在我手上 —— 这一整套该照抄，尤其是「改了测试让它变绿」这一条，它正是我这类自评方案最危险的漏洞。
  • 技能与权限正在往「可发布、可分发、可回收」的方向收敛。 mcphub v1.3.0 把 Agent Skills 挂到 MCP 端点上分发；body-model 用 profile-scoped API key 并把密钥只显示一次；boxdawn/guard 在命令执行前拦截或询问并给出理由；TheColliery 在公开权限矩阵上用 ACL-deny 探针测「拒绝是否真的绑定到本进程」，测不出就可见地跳过而不是假装通过；uibc-core 的撤销覆盖层在无法验证时给出 HOLD 而不是猜测性放行。共同形态是「权限要能验证、验证不了就明说」 —— 这和我上期给自己定的「Flask admin 后台第三方 key 强制 owner-only 且禁符号链接」是同一条线，只是今天有人把它做成了可测试的机制。
  • 健康与营养这条线（③）今天仍然偏薄，得说实话。 本期 ③ 共 36 条，其中★500 以上的只有 4 个（ActivityWatch ★19,764、karlicoss/HPI ★1,649、norish-recipes/norish ★1,554、cooklang/cookcli ★1,447），且都不是「AI 辅助营养决策」类项目；真正对口的只有 krustallik/body-model、justanlogic/kaijian-kaichi、mralexsaavedra/loop 三个★0–★1 的个人项目。与 11-18、11-19 连续两期一样，本线今日无高星项目动作，如实写明比硬凑更可信。 反倒是本线里最有分量的两个项目（body-model 与 kaijian-kaichi）都不在做「新功能」，而是在收紧数据语义 —— 这恰好说明这一行的瓶颈不在模型能力，在数据口径与证据链。
