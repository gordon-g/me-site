  • 风格来自期刊实测而非提示词：参考语料是 33 篇开放许可的原创研究论文（JAMA Surgery、JAMA Network Open、Lancet、BMJ、Nature；2019–2022），仓库里只存聚合数字、通用短语、来源 DOI 与许可证，不存论文全文。个人风格学习门槛是至少 3 篇论文 + 30 句，且永不低于期刊 p90。

值得关注的原因

  • "explicit association caps a sentence at associative"这一条，就是我公众号内容的护栏。 我做循证内容（4P精准营养观察、健康100新一观察），一直要求"零 AI 幻觉、必须附参考文献"。但"有参考文献"和"结论强度不超过证据强度"是两件事——一篇引用了横断面研究的文章写"某干预改善了动脉粥样硬化"，引用是真实的，结论是越界的。ManuWright 把这件事做成了可执行的检查：证据台账里给每条证据标注能支撑的最强措辞，越级就报错。
  • "允许用 None 明确声明证据缺口"这个设计，可以直接搬到 GRPM 的报告里。 我的营养基因组学建议里，某条 SNP 证据不足时，现在的做法是"不给建议"。改成"显式写明这个靶点证据不足" 反而更有用——关键是让"缺证据"成为一个被声明的事实，而不是一个沉默的空白。这与上一期记下的"证据不足必须是独立结论"完全一致。
  • "图表直接从结果 CSV 绘制并带溯源"（v1.10.1）对我做干预报告图表是现成的解法。 我的 GLP-1 营养伴侣有"化验指标趋势追踪"，图表目前是前端自己画的——让图表从落库的结果数据直接生成并带溯源，能消除"图上的数跟库里不一致"这类问题。
  • 撤稿 / 关注声明 / 勘误检查，是循证内容最容易被忽略的一环。 我引用文献时通常只核对"有没有这篇"，不核对"这篇有没有被撤稿"。 ManuWright 把它做进了常规审计流程。
  • 风格学习的三重门槛（3 篇 + 30 句 + 不低于 p90）值得抄。 我做内容有个长期困扰：既想让 AI 保持我的个人风格，又不想它学成模板腔。"至少 3 篇 + 30 句才允许启用，且永远不能低于期刊 p90"——这给了"学习个人风格"一个可执行的准入门槛和上限。

窗口内 5 次提交（11-01 21:34Z ~ 11-02 05:38Z），全部围绕"怎么让人相信这个结果"。

  • 项目的第一句话就把立场说死了："The goal is evidence a reviewer can inspect: which records supported an answer, which SQL actually ran, what failed, and why a reviewer accepted or rejected a result. Aggregate scores alone are not clinical validation."

值得关注的原因

  • "Aggregate scores alone are not clinical validation"这一句，正好点在我 4P 平台的软肋上。 我的干预报告有 9 章结构、24 个风险维度、6 个风险级别——这本质上就是一个总分 + 分项。这个项目提供的不是另一个评分体系，而是"评分之外还要留什么" 的清单：支持这个答案的是哪些记录、实际跑的是哪条 SQL、哪里失败了、复核的人为什么接受或拒绝。把这一套搬到 4P 平台，就是我上一期记的"干预报告落库 checklist"的完整版。
  • "未知的版本号 / 模型细节被记为缺失，而不是用工作区的钉死值替换"是一条救命规则。 我做报告时经常遇到这种情况：模型换了、提示词改了，但报告里的结论还在，而且看不出是基于哪个版本生成的。宁可写"未知"，也不要用当前工作区的值去填历史记录的坑——这与上一期 yantrikdb 那个"同一进程内第二个 SQLite 实例会静默损坏存储"是同一个教训的另一面：不要用看似合理的东西填补你不确定的东西。
  • "离线重生成必须用当时捕获的输入"这条，可以直接变成 4P 平台的报告存档要求。 我的化验 OCR→AI→App 导入管线一直在做"每次交互数据持久化以支持自我进化学习"，但如果重生成一份历史报告时用的是今天的模型和今天的知识库，那份报告就不再是当初给用户看的那份了。输入包要整体归档，这一条现在就值得加。
  • "LLM 提案仅供参考，已接受的数据映射 / 变换必须可评审且确定性"——这正是我在 GRPM 报告里的边界。 SNP 到补剂建议的映射里，哪些是规则（可审计、可复现）、哪些是模型生成（仅供参考），必须分清楚，否则用户分不清哪些结论能追溯。这条同时也是合规要求。

三、今日趋势观察

今天的 134 个条目里，最值得注意的不是哪个仓库涨了多少星，而是"证据与授权"这两件事正在从"文档里的善意提醒"下沉成"代码里的硬约束"。四个方向上是同步发生的。

  • 第一，许可证正在从"一个字段"变成"三个字段 + 一次审计"。 ClawBio/ClawBio 把每个技能的授权拆成 license / model_license / data_license 三项并规定取最严者，还明确写着"空 = 未声明，绝不等于宽松"；它对 96 个技能做了一轮审计，结果是 92 个 MIT、1 个 Apache-2.0、1 个 GPL-3.0、1 个 PROPRIETARY、1 个未声明。"代码是 MIT"不等于"这个项目可以商用"——技能、模型权重、参考数据三层可能各有条款。 对要做成产品的一人公司，这一层不查清就动手是硬伤。
  • 第二，"结论强度不得超过证据强度"开始有工具了。 grotyx/Academic_writing_c_claudecode 的规则是"explicit association caps a sentence at associative"——证据只支持关联时，措辞不许升级成因果；配合撤稿 / 关注声明 / 勘误检查、DOI 一致性检查、以及"允许用 None 声明证据缺口"。这是内容合规与科研诚信的交叉点，也是我做循证公众号最缺的那把尺子。
  • 第三，临床 AI 评测的共识从"给一个分"转向"留一整包可复核的证据"。 pmanko/clinical-ai-validation-harness 直接写明"Aggregate scores alone are not clinical validation"，要求每次运行落 run_manifest.json + events.jsonl + results.jsonl + trace，并且未知的版本号记为缺失而不是拿工作区的钉死值替换；athril/agentic-target-evidence 用六个独立视角（遗传 / 生物学 / 安全性 / 临床 / 商业 / 监管）给一个靶点打分并产出带溯源的 dossier，且 README 明确写"Every verdict is LLM-generated over retrieved evidence — a preliminary research aid, not ground truth"。两个独立项目，同一句潜台词：多视角 + 显式免责声明，比一个更精细的分数更诚实。
  • 第四，健康类产品的形态正在分化成"全栈 OS"与"单点 MCP"两条路，而且两边的默认值都变了。 zilet/cairn 走全栈路线——自托管、一个 SQLite 文件、PWA + REST + MCP、教练团队读全部数据后只给一件事、不打分不催促、能自动落地的小改动都带一键撤销；davidmosiah/wellness-nourish、Aryan-Jhaveri/mcp-foodguidecanada、deadletterq/mcp-opennutrition、StefanOOEOrg/mcp-food 走单点路线——把一个数据源包装成 MCP 供 agent 调用。值得注意的是两条路的默认值都是"本地优先 + 数据不出本机 + HTTP 只绑 127.0.0.1"（wellness-nourish 本期 13 次提交里有一半是安全加固：限制未认证 HTTP 只能绑 loopback、迁移前拒绝预置的 profile 符号链接、序列化并限制共享 profile 持久化、加固 MCP 输入预算；foodguidecanada 的 44 次提交里也专门做了"24 个工具的只读、非 root 的 HTTP 冒烟测试"）。"本地优先"已经不是个人偏好，而是这类产品的默认架构假设。
  • 第五，agent 的"工具层"正在被重新设计成"像 IDE 一样的东西"，而不只是加几个 API。 cortexkit/aft 的做法是劫持宿主原有的 read / write / edit / bash 工具槽位，把底层换成 tree-sitter 解析、索引检索、输出压缩与符号级操作，再叠加 aft_ 系列工具；配套的是逐文件撤销栈 + 命名检查点，以及"列表被截断时必须显式说明 shown N of M"这类输出契约。同一时期 fallow-rs/fallow（21 次提交）、repowise-dev/repowise（10 次）、DeusData/codebase-memory-mcp（17 次）都在做代码库健康度与结构化检索——"让 agent 先看见结构、再动手"已经是共识，而"改完能撤回"正在从加分项变成底线。
