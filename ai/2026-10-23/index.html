1. Vector Institute 开源 Odyssey：可解释的患者时序基础模型，把"每个声明都可证伪"写进了工程

地址：https://github.com/VectorInstitute/odyssey ｜ ★62 ｜ Python ≥3.12 ｜ 附 arXiv 论文，当日仍有提交

事件内容
Vector Institute 开源了患者临床时间线的可解释基础模型：数据从 MIMIC-IV / eICU-CRD / GEMINI 经 MEDS 抽取与分词进入主干，输出事件预测、校准的生存曲线、告警与概念读出。架构上默认 hybrid 主干（Mamba-2 块与 chunk 局部注意力交错，按"持久打包的患者车道"截断反传，任意长度病历流式处理、每步常数显存），并保留 transformer 对照臂以证明结论不依赖主干。核心是概念瓶颈模块：概念标签来自 LOINC 索引的规则注册表（KDIGO AKI 三条腿、Sepsis-3、SIRS、qSOFA、升压药暴露等），标签随病历展开即时计算、绝不从事后事件回填；选中一个概念会对隐状态产生精确、已知的位移——同一推力也可作为训练期损失（steering）。

README 开头即声明"这不是诊断系统、不声称序列模型打得过定制基线、也不是构造意义上的可解释"，并给每个声明配了测试，注册表里记录模型哪里不行。当日提交为依赖安全升级（pillow 13.0.0）。

值得关注的原因

  • 医疗时序建模这个方向开源项目不少，但把"可证伪"当成工程纪律的极少：概念标签不回填、概念→隐状态的位移可精确计算、每个 claim 配测试、failures 进注册表。这给"模型可解释"提供了可复核的落地样本，而不是 README 口号。
  • 对医学研究场景直接可用：Sepsis-3 标签经过独立重实现验证、29/29 数据源规则全覆盖、阈值与 checkpoint 一起版本化——这套"临床规则注册表"的做法，做队列研究或医院内部回顾性分析可以直接抄。
  • 反面参考也有价值：它明确不做诊断系统，说明研究级医疗开源正在形成"能力声明收敛"的默契，和之前几期"合规写进代码路径"的趋势一脉相承。

2. Google 官方发布 Elephant-Goldfish Model：规格驱动开发插件，用"零上下文子代理"给规格书做压力测试

地址：https://github.com/google/elephant-goldfish-model ｜ ★165 ｜ Apache-2.0 ｜ 跨 harness 插件，当日合入 Claude 读钩子

事件内容
Google 开源的 EGM 是一个面向 AI 编程代理的规格驱动开发（Spec-Driven Development）插件：深度上下文的 Elephant 会话负责起草规格书，然后由一群零上下文的 Goldfish 子代理对规格做压力测试——每个 Goldfish 只带单条规格条款、不带开发会话的任何上下文，专门找漏洞，再在你写第一行代码之前把问题修掉。安装面覆盖极广：直接让任意 agent Install <repo>、Antigravity（agy plugin install）、Claude Code（plugin marketplace）、Codex、Claude Cowork / ChatGPT 各有路径。命令面包括 /egm-brainstorm（探索问题边界 + Goldfish 群初测）、draft 等流水线命令。当日提交修了 bootstrap prompt 截断，并合入"Claude 转录读取 + PreToolUse 钩子批准插件文件读取"。

值得关注的原因

  • 这是继 android/skills、NVIDIA/skills 之后又一家平台厂商把"方法论"做成官方插件，而且赌的路线很清晰：与其让模型一次性记住全部上下文，不如用无污染的旁观者反复审查规格——"零上下文"正是它卖点的核心，上下文污染被明确当作被测对象的属性而非 bug。
  • 安装路径表格值得注意：EGM 把 Antigravity、Claude Code、Codex、"任意 agent"并列为一等公民，官方技能的跨 harness 化在加速，技能层正在事实标准化。
  • 对团队的直接含义：写规格 → 子代理红队 → 再写码，这个流程可以低成本移植到任何 harness 上试用，尤其适合医疗健康类"改错成本高"的业务需求文档。

3. Nous Research Hermes Agent：256k★ 的开源 Agent Harness，把"环境随用随睡"做成了默认能力

地址：https://github.com/NousResearch/hermes-agent ｜ ★256,253 ｜ MIT ｜ 全平台安装器，Windows/Android(Termux) 原生支持

事件内容
Nous Research 的 hermes-agent 本周冲到 25.6 万星，当日在 main 分支持续修 Windows 桌面端构建（uv 缓存路径问题）。能力清单：内置 cron 调度器（自然语言定义日报/备份/审计等无人值守任务）；子代理并行（Desktop 里可选每个子代理的 provider、模型与限额，还能用 Python 经 RPC 调工具，把多步流水线折进零上下文成本的一轮）；六种终端后端——local、Docker、SSH、Modal、Daytona、Vercel Sandbox，外加 Singularity/Apptainer 插件后端，其中 Modal/Daytona 提供 serverless 持久化：agent 环境空闲即休眠、按需唤醒，空闲期成本趋近于零，"$5 VPS 跑得动，GPU 集群也跑得动"；并支持原生 Windows（CLI/网关/TUI 无需 WSL）与 Android/Termux 签名 APT 源。还带"研究就绪"模式：批量生成轨迹 + 轨迹压缩，用于训练下一代工具调用模型。

值得关注的原因

  • harness 赛道已经白热化（OpenHands、deer-flow、openhuman 同日活跃），Hermes 的差异化押注很明确：把环境成本做成调度问题——休眠唤醒 + 六后端统一抽象，这对"几百个 agent 排队干活"的成本结构是数量级级别的改动。
  • 它把"轨迹生成/压缩"当产品功能输出，开源 harness 直接变成训练数据工厂，模型厂与 harness 厂的边界在被这种项目重画。
  • 医学/健康管理场景里大量任务本质是"定时 + 长时运行 + 低频交互"（随访提醒、夜间报表、饮食审计），cron 调度 + 休眠环境 + 多后端这套组合几乎是按这个形状设计的。

4. php2shell（CVE-2026-109618/109619）生态爆发：CVSS 9.2 的 PHP 预认证 RCE，PoC、扫描器、官方检测器同窗出现

地址：https://github.com/ikow/php2shell-poc ｜ ★1,526 ｜ 另见 https://github.com/assetnote/php2shell-scanner（★294）、https://github.com/eness/php2shell-bypass-aslr-exp（★958）、https://github.com/openai/php2shell-checker（★823，昨日已推）

事件内容
PHP session.upload_progress 与 Zend 引擎 OOM bailout 组合出的两条 CVE 持续发酵：5 条独立预认证 RCE 链，影响 PHP 5.4.0（2012）至 8.5.11 共 14 年的代码，部分链路无需应用层任何漏洞，波及约 78% 的网站（WordPress 43%、Joomla、Drupal、Laravel、Magento 及所有默认 PHP 配置）。修复版本为 8.2.35 / 8.3.36 / 8.4.27 / 8.5.12。24 小时内 GitHub 上出现完整的攻防生态：ikow/php2shell-poc（1526★，含 Suricata/Sigma/ModSecurity 检测规则）、eness 的免改官方版 exploit（958★）、assetnote 高保真扫描器（294★）、OpenAI 官方 checker（823★，昨日已推，今日仍在星标增长），另有多个付费 exploit 流通。

值得关注的原因

  • 这是本期对"自托管健康/营养应用"最实际的安全警报：此前推送过的大量个人健康记录、饮食追踪、MCP 网关类项目不少跑在 PHP 栈上，一旦底座 PHP 未升级，agent 读写的健康数据（PHI）直接暴露在预认证 RCE 面前。
  • 攻防双方 24 小时内同时完成供给（PoC + 检测规则 + 扫描器 + 厂商 checker），开源安全的响应周期已经压缩到"天"级——运维侧的排期逻辑也要跟着变，不能按周算。
  • 事件还演示了一个新常态：AI 厂商下场发检测工具（OpenAI checker）成为漏洞响应的一环，"模型+代码"混合审计在安全事件里的角色正在固化。

5. Bernstein：给 AI Agent 写"声明式治理层"，规则一写、执行层自动拦截

地址：https://github.com/sipyourdrink-ltd/bernstein ｜ ★1,372 ｜ PyPI + GHCR 发行 ｜ 当日仍在持续发依赖安全更新

事件内容
Bernstein 定位为 AI agent 的开源治理层：把规则用声明式的方式写下来，由它统一强制执行——agent 想做什么动作，先过这层"写好的规矩"，违规操作被拦下并产生审计痕迹。工程形态成熟：已发 PyPI 包与 GHCR 镜像、CI 完整，当日在跟进依赖安全升级（certifi 2026.10.19 等），一周内有 6600+ 号的 PR 流水，社区活跃度与代码量都超出"个人项目"量级。

值得关注的原因

  • 之前两期我们跟踪过"技能供应链治理"（NVIDIA/skills 的 OMS 签名、aiskillstore 的安全审计市场），Bernstein 把同一件事往下推了一层：不治理"技能从哪来"，而是治理"agent 运行时能做什么"——这两层合起来才是完整的 agent 治理栈。
  • 它与 bernstein 式声明规则对医疗场景是刚需：PHI 访问、外发数据、付费 API 调用这些约束，靠 prompt 约束不可靠，靠每个 agent 自查也不可靠，声明式 + 统一强制执行 + 审计痕迹恰好是合规审计要的形态。
  • 当选第五条而非 openfoodfacts（后者今日为维护性提交）的原因：治理层是本周明显的新趋势节点，而 openfoodfacts 作为营养数据底座已在分类表中保留，读者可两处对照。

三、今日趋势观察

  1. Harness 白热化后的差异化押注：hermes-agent（环境休眠 + 六后端）、openhuman（$10 VPS 跑 500 agent）、deer-flow（沙箱生命周期）、omnara（托管关机语义）同日活跃，说明 harness 竞争已从"能跑"转向成本结构与生命周期管理——谁把 agent 的空闲成本和崩溃恢复做到数量级领先，谁就留在牌桌上。
  2. 平台厂商继续把"方法论"产品化：Google EGM 用"零上下文子代理审查规格"把 Spec-Driven Development 做成官方插件，与 android/skills、NVIDIA/skills 的路径一致——技能层正在从社区自发走向官方供给 + 跨 harness 标准安装，选型时官方插件的权重应该上调。
  3. 研究级医疗开源出现"反叙事纪律"：Odyssey 开篇声明"这不是诊断系统"，每个 claim 配测试、失败进注册表；连同昨日 notepilot 的自认 tripwire，主动划清能力边界正在成为医疗 AI 加分项，评审者（包括我们）应把它当作成熟度信号而非示弱。
  4. Agent 治理栈成形：供应链层（技能签名、审计市场）与运行时层（Bernstein 声明式拦截）在同两周内成熟，"先可信再智能"（10-21 期观察）有了具体的产品形态；医疗健康业务接下来该做的不是问"要不要治理"，而是选两层里先落哪一层。
  5. php2shell 提醒：自托管健康应用的底座债：影响 78% 网站的预认证 RCE，24 小时内攻防生态齐备。此前推送的自托管健康/营养/MCP 项目应尽快核对 PHP 修复版本（8.2.35+/8.3.36+/8.4.27+/8.5.12+），健康类信息安全小专栏（10-20 期提议）从本期开始正式跟踪此类事件。
