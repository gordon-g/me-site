1. The research agent now offers a "physically isolated" mode: code has no network, literature is searched locally

URL: https://github.com/openscientist-io/openscientist ｜ ★130 ｜ Apache-2.0 ｜ The open-source implementation behind the Nature Medicine paper "An open agentic AI co-scientist for clinical and biomedical discovery": given a research question and data files, it searches literature, runs analyses, and proposes and tests hypotheses

What happened

  • 3 commits today (merging the feat/admin-grant-admin and feat/delete-feedback PRs): what was added today is admin-side permission granting and user-feedback deletion, not model capability itself.
  • The project states its own purpose plainly in the README: An autonomous AI scientist that generates and tests hypotheses from scientific data — give it a question and (optionally) data files, and it explores the data, searches the literature, runs analyses and writes up a report of its findings.
  • The official docs/airgap.md defines an air-gapped mode, explicitly intended for sensitive data such as clinical records or unpublished results: containers running the analysis start with networking disabled; the agent container sits behind a default-deny firewall and can reach only the database, the internal execution broker and the model endpoint; literature search switches to a local PubMed/MEDLINE baseline of about 40 million articles in PostgreSQL instead of hitting NCBI.
  • Air-gapped mode is available on self-hosted installs only — the hosted site www.openscientist.io does not offer it. An admin can toggle it under Admin → Settings, or force it on with OPENSCIENTIST_AIRGAPPED=true in .env so it cannot be switched off from the panel.
  • The most recent release inside the window is v0.2.0 (2026-11-16), with the paper published in Nature Medicine in the same period.

Why it matters

  • For my field this is a method-level signal, not a tool recommendation. The thing I have long worried about — "AI takes part in clinical research, but the reasoning isn't inspectable and the data has to leave the machine" — has an engineering answer here: make "data never leaves your infrastructure" a switch rather than a promise. All three gates (container with no network, default-deny firewall, local literature corpus) are verifiable configuration, not a line in a document.
  • The local PubMed baseline lands directly on my retrieval path. When I do nutrition-genomics and functional-medicine research, literature evidence must be citable and traceable; if the agent runs against a local mirror, every claim it makes can land on a fixed corpus rather than on a different result set each time. That is the engineering answer to "evidence-based plus zero AI hallucination" — not demanding a more accurate model, but pinning down where its evidence comes from.
  • For my 4P precision-nutrition platform and the GRPM nutrition-genomics system, a project where self-hosting, auditability and a local literature corpus all hold at once is rare. Most AI research platforms (Google AI Co-Scientist, Sakana AI Scientist, GPT-Rosalind, Biomni and others) are closed source — not because anyone dislikes openness, but because outside researchers simply cannot inspect how they reached their conclusions. Since I have to deliver evidence-grade capability to students and clients, auditability is a hard requirement.
  • The 3 commits today are themselves unremarkable, and that is the signal: a project that has just published a paper is now doing things like "can an admin delete a piece of feedback" — operational concerns. That means it has moved past paper demonstration into real deployment. The most quotable figure from the paper (a median cost of about USD 11.3 per run) comes from the paper's own reporting, not from the repository, so this issue sticks to README and documentation text and keeps paper numbers out of the body.

3. Code review starts using a deterministic rule engine to rein in natural-language skills: Alibaba's v1.14.1 writes "unstable quality" into the README

URL: https://github.com/alibaba/open-code-review ｜ ★55,440 ｜ Apache-2.0 ｜ Alibaba's hybrid-architecture code review tool: deterministic pipelines plus an LLM agent reviewing in both directions, precise line-level locations, built-in multi-language rule sets (NPE, thread safety, XSS and more)

What happened

  • 7 commits today, with v1.14.1 released inside the window; the commit types are mixed: feat(i18n): add Turkish README, site docs and VS Code localization, fix(rules): recognize BOM-prefixed Objective-C source, refactor: adopt modern Go stdlib helpers, fix(tool): reject workspace named pipes before opening, fix(examples): fail GitFlic and Gerrit jobs when ocr review fails.
  • Two of them bear directly on the review criteria themselves: docs(skill): respect review-only intent for mispositioned findings (respect the intent of "review only, do not modify") and feat(skills): include behavior and impact in native and delegated reviews (include behaviour and impact in both native and delegated reviews).
  • The README states the design premise clearly: "If you've used general-purpose agents like Claude Code with Skills for code review, you've likely encountered these pain points — unstable quality: natural-language-driven Skills are hard to debug, and review quality fluctuates significantly with minor prompt variations."
  • The corresponding answer is the core design: deterministic engineering × agent hybrid — rules are matched finely against each file's characteristics so the model's attention stays narrow, and the README calls template-engine-based rule matching "more stable and predictable" than purely language-driven rule guidance.
  • Two modes of use, native and delegate, each with its own skill (open-code-review and open-code-review-delegate); both require Git >= 2.41 and the ocr CLI, and only native mode needs an OCR model provider. Installation is npx skills add alibaba/open-code-review.

Why it matters

  • The README line "natural-language-driven skills are unstable in quality" is the sharpest sentence I read today, because it describes exactly where I am: my 4P expert package's two-way comparison evaluation is, in substance, a fully self-referential loop — LLM writes the questions, LLM writes the answers, LLM does the scoring — and the README says plainly that this kind of approach fluctuates with small prompt variations. Alibaba's answer is not to write better prompts but to move part of the judgement back into a deterministic rule engine — a concrete engineering form of "a self-scoring loop needs external pins", sharper than the "add deterministic external tests" I noted last issue: rule matching has to land on file characteristics, not on the model's attention.
  • "Review only, do not modify" being written into the skill layer as an intent constraint is exactly the boundary my report generator and self-evaluation system lack. Right now my intervention report generator has no "evaluate but do not modify" mode: once self-evaluation triggers, the artifact can end up being edited as a side effect. Intent has to be part of the artifact, not merely a word the caller remembers to say.
  • fix(tool): reject workspace named pipes before opening deserves a look on its own: refusing named pipes before opening a workspace file treats "opening a path" as potentially untrusted input. My 4P platform imports lab-report PDFs and images, and those "path-as-input" places need the same check.
  • Apache-2.0 on top of ★55,440, installable with one command via npx skills add into Claude Code / Codex / Cursor / Kimi Code — this is exactly the delivery shape I want for the 4P expert package: the deliverable has to be a single install command that runs inside whatever agent the user already has.

4. The gateway starts catching the model for you: Manifest makes "fall back to another model on failure" and "account for every cent" the default

URL: https://github.com/mnfst/llm-gateway ｜ ★7,650 ｜ MIT ｜ An open-source LLM gateway: API keys, subscriptions and local models behind one OpenAI-compatible endpoint, with on-demand routing, automatic fallback to another model on failure, and per-call accounting

What happened

  • 4 commits today, with manifest@6.29.3 released inside the window; every commit fixes a real fault: fix(backend): map saved reasoning_effort/max_completion_tokens on Responses routes, fix(backend): map Gemini LANGUAGE and IMAGE_* block reasons to content_filter, List the GPT-6.1 Sol Bedrock Runtime profiles in model discovery.
  • The README positions it as "AI Agents that don't break", and lists five core capabilities: custom routing (API keys, subscriptions, local models, custom providers), full body logs for success and error messages, tracking every single dollar with notifications and limits set, and falling back to a different model when a query fails, self-healing bad requests.
  • Deployment paths are broad: one-click to Render, Railway, AWS CloudFormation and GCP Cloud Shell, with the Docker image manifestdotbuild/manifest.
  • Note the direction of these three fixes: mapping saved reasoning_effort and max_completion_tokens onto Responses routes (previously the parameters were stored but never applied), mapping Gemini's LANGUAGE and IMAGE_* block reasons uniformly to content_filter (previously safety interceptions were mixed in with other causes), and adding GPT-6.1 Sol's Bedrock Runtime profiles to model discovery.

Why it matters

  • "Fall back to another model on failure" plus "account for every cent" together are a working reference for exactly what I am doing. I have a local Ollama, a gateway such as OpenRouter, and a concrete history of the domestic client hard-coding foreign providers out of the UI and of relay quality varying widely — but none of my calls have a unified accounting layer and none have any automatic fallback. A failure today is just a failure, after which I manually switch provider and retry. Automating "fail → switch model → retry" turns "the model is unavailable" from a recurring incident into a handled branch.
  • reasoning_effort being stored but never applied is a bug only large-scale use exposes. I have hand-written parameters like reasoning_effort into models.json — parameter stored, request sent, server silently ignoring it, and nothing on my side indicates a problem. This is the canonical shape of silent failure: everything looks normal except the result is worse than expected. Fixing it on the gateway amounts to admitting that "the parameter got swallowed" is a real fault class.
  • Mapping Gemini's safety interceptions separately from other block reasons is an honest error taxonomy. Content blocked by a safety policy, a malformed request and a model timeout are three different things — lumping them together leaves users guessing. This is the same principle as last issue's clinosim requiring an order before saying "management started": errors must also state what they are.
  • MIT licence, an OpenAI-compatible endpoint, self-hostable — it can sit in front of my existing call chain without touching client code. For a one-person company on roughly 8 hours a week and about a month of cash runway, "does not break plus you can see what it cost" outrank any new capability.

3. Trends today

  • ⭐⭐⭐ "Data never leaves the machine" moved from a principle to a tickable configuration today. openscientist-io/openscientist's air-gapped mode gives three concrete gates: analysis containers start with networking disabled, the agent container sits behind a default-deny firewall (reachable only by the database, the internal execution broker and the model endpoint), and literature search switches to a local PubMed baseline in PostgreSQL (about 40 million articles), with self-hosted installs only; 14790897/sleep-secret stresses that "audio never leaves the device, no account and no server"; GeiserX/OwnGenome is a 100% local, Docker-powered whole-genome pipeline; GeiserX/OwnHealth pulls labs, records, wearables and genome into one self-hosted store; ulsklyc/yuvomi and TraceApps/nutritrace respectively claim "your data stays yours" and "no telemetry, no cloud sync"; cactus-compute/cactus squeezes an on-device agent into under 50MB. Six unrelated projects doing the same thing: turning privacy from a promise into a set of configurations and deployment shapes. The most direct mapping for my field: if my health data platform is to be delivered to institutional or enterprise clients, "data never leaves the infrastructure" has to be a configurable switch, not a line in a document — which my 4P platform does not yet have.
  • ⭐⭐⭐ Authorization, validity windows and audit events were broken out into first-class citizens. nightscout/nocturne states that "a grant is honoured, and a delegation minted, only while its subject is active", adds "the owner step resumes only the subject it recorded for the tenant" and "joining and leaving are audit events of their own", alongside team invite links, manager/operator switching and the Caretaker role; iflytek/skillhub makes RBAC and audit logs standard in an enterprise skill registry; GeiserX/OwnHealth keeps "held mail, unassigned documents and refresh tokens unreadable" without a key; Yinglianchun/Serein clarifies referents and attribution before writing an event. Five cuts of the same thing: permission is not a boolean but a series of events carrying a time window, an owner and an audit trail. My GLP-1 nutrition companion already has a multi-member "family health record" concept; what it still lacks is exactly this subject-plus-validity-plus-audit-event trio.
  • ⭐⭐ Natural-language-driven skills were publicly named as quality-unstable, and deterministic rule engines started taking over judgement. alibaba/open-code-review writes it straight into the README — "natural-language-driven Skills are hard to debug, and review quality fluctuates significantly with minor prompt variations" — and answers it by moving part of the judgement back into a template-based rule engine matched to file characteristics (which it calls more stable and predictable than purely language-driven rule guidance), while shipping both native and delegated modes as two separate skills; intellectronica/ruler does the minimal version of the same thing, applying one rule set to every coding agent; chgagne/claude-skills-research's commit log today reads "comparing-papers closed after C3" and "C3 results: axis answer table does not widen comparing-papers reviews (real non-plant issues 0)", accepting the review skill against numbered experiments and a count of zero real non-plant issues. "Real non-plant issues 0" is the most solid line I read today — it turns "is this review skill good" into a countable fact rather than an impression.
  • ⭐⭐ Parameters being silently swallowed was the fault class fixed again and again today. mnfst/llm-gateway fixes saved reasoning_effort / max_completion_tokens not being mapped onto Responses routes, fixes Gemini's LANGUAGE and IMAGE_* block reasons not being mapped uniformly to content_filter, and adds GPT-6.1 Sol's Bedrock Runtime profiles to model discovery; GeiserX/OwnGenome fixes the case where, under INPUT=vcf, it now says the BAM was not read instead of reporting "No BAM found"; Yanstd888/9routerx fixes empty trailing user turns being dropped; agentclientprotocol/registry updates agent versions daily. Four fixes pointing at one class of problem: the request goes out, the server accepts it, one layer never takes effect, and the caller sees no signal. The expensive part is precisely that it raises no error — and none of my own calls have that verification layer today.
  • ⭐⭐ The health line's centre of gravity today is sharing and attribution, not recording and display. nightscout/nocturne spreads teams, invite links, manager/operator switching, the Caretaker role and joining/leaving audit events across a single day; Paco5687/GlucoPilot brings lab tests into the clinical hypothesis list (which is exactly what today's new commit does); GeiserX/OwnHealth imports LibreView and Dexcom Clarity CSVs while also pulling workout heart rate, distance and energy from FIT files; andreroxhage/meal-prep-agents works on household common-sense constraints like "don't buy what the list says is at home". All four are answering the same question: when this health data flows between several people, who can see what, and who is responsible. My "family health record" is not enough if it only covers multi-member plus timeline plus export — this layer is still missing.
